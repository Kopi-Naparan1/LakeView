# Website Price Proposal

## Lake View Website Pricing Guide

This document is a practical pricing guide for this specific website based on:

- the actual codebase and scope of work in this repo
- the Philippine market
- the fact that this is your first website project

This is written to help you quote this project properly and also to help you price similar work in the future.

**Pricing date basis:** March 31, 2026  
**Market location:** Philippines  
**Perspective used:** first-project freelancer pricing  
**Quote style:** build only

---

## 1. Short Answer

For this exact website, my recommended first-project freelancer price range is:

- **Minimum:** **PHP 22,000**
- **Maximum:** **PHP 35,000**

If you want one practical number to actually say to a client, the safest recommendation is:

- **Recommended quote:** **PHP 28,000 to PHP 32,000**

If you want a simple one-line offer, you can quote:

> **PHP 30,000 build only, excluding domain, hosting, and monthly maintenance**

That is a fair beginner quote for this website without severely underpricing yourself.

## 2. Why This Website Is Not Just a Cheap Template Job

This repo is not a one-page placeholder site.

Based on the actual codebase, this website includes:

- a custom React + Vite frontend
- multiple routed pages
- responsive header and mobile drawer navigation
- custom visual sections with image-heavy layouts
- homepage hero and multiple supporting sections
- dedicated cafe page
- dedicated resthouse page
- dedicated contact page
- Google Maps embed
- custom forms for message and booking request UI
- performance work for route loading and deferred sections
- reusable shared components such as `AppImage` and `DeferredSection`

This means the work is closer to a custom small business brochure website than to a basic drag-and-drop starter site.

Even though there is no backend, no e-commerce, and no CMS, it is still:

- custom-coded
- multi-page
- branded
- responsive
- content-structured
- more involved than a simple landing page

That is why the price should not be "very cheap beginner only."

## 6. Why I Would Not Price It Lower Than PHP 22,000

If you go too low, you create three problems:

### 1. You make custom work look like template work

This site is already more than:

- a one-page promo site
- a Facebook-only presence
- a drag-and-drop starter

### 2. You forget the real work behind the site

Even without backend work, this project still includes:

- planning
- section design
- component development
- responsive behavior
- content structure
- image handling
- optimization work
- testing
- revision time

### 3. You make your next quote harder

If your first project is priced far too low, future clients will expect the same.

That makes it difficult to grow your pricing later.

So while this is your first project, you should still avoid "rush beginner pricing" like:

- PHP 5,000
- PHP 8,000
- PHP 10,000

Those amounts are too low for this scope unless you are intentionally doing a favor or portfolio giveaway.

## 7. Why I Also Would Not Push This First Project Too High

Even though the site is custom-coded, it still has limits:

- no backend
- no live data integrations
- no full booking system
- no CMS/admin
- no e-commerce

So for a first website, charging something like:

## 10. Optional Add-On Pricing

These are reasonable separate add-ons for the Philippine market and your current level.

### Launch / deployment setup

If the client wants help putting the site online:

- **PHP 3,000 to PHP 6,000**

This can include:

- deploying the site
- connecting the domain
- basic hosting setup guidance
- final online checks

### Monthly maintenance

For small edits and support:

- **PHP 1,500 to PHP 4,000 per month**

This can include:

- text changes
- image replacement
- minor layout adjustments
- dependency updates
- basic uptime checks

### Content/image upload assistance

If the client still needs help organizing and inserting their content:

- **PHP 2,000 to PHP 5,000**

### Domain and hosting

These should usually be:

- **billed separately at actual cost**

Do not guess the price into your main quote unless you are managing it yourself.

### Functional add-ons for features not yet implemented

These are especially important because the current repo already has the front-end UI for forms, but not the real submission logic behind them.

Right now:

- `src/Pages/Contact/ContactForm/ContactForm.jsx` is a UI-only contact form
- `src/Pages/Resthouse/Booking/Booking.jsx` is a UI-only booking request form

That means they are present visually, but they are not yet sending real data anywhere. Because of that, they should be quoted as separate paid features.

#### Email sending logic

If the client wants the contact form to actually send messages to an inbox:

- **Contact form email sending only:** **PHP 3,000 to PHP 6,000**

If the client wants both the contact form and booking request form to send real emails:

- **Contact + booking email sending:** **PHP 6,000 to PHP 10,000**

If the client also wants a more production-ready setup with:

- input validation
- loading, success, and error states
- spam protection
- provider setup
- testing and debugging
- cleaner email formatting

then a better quote is:

- **Full email form setup:** **PHP 8,000 to PHP 15,000**

#### What "email sending logic" usually includes

This add-on can include:

- wiring the form to a real provider such as EmailJS, Formspree, Web3Forms, Brevo, Resend, or a custom backend
- connecting inputs to a real submission flow
- validation of required fields
- handling duplicate submissions and request states
- basic anti-spam protection
- testing if emails are actually received correctly

#### Important pricing rule for email features

Your labor fee and the email service cost are not the same thing.

You should normally charge:

- your one-time implementation fee
- plus any third-party service subscription separately if the chosen provider is paid

So a good way to pitch it is:

> Website build: **PHP 30,000**  
> Contact form email sending add-on: **PHP 5,000**  
> Booking form email sending add-on: **PHP 3,000 to PHP 5,000**

That makes the total:

- **PHP 35,000** with contact form sending
- **PHP 38,000 to PHP 40,000** with both forms sending

#### Other not-yet-implemented feature values

If the client asks for more than just email sending, these are reasonable add-on ranges for your level:

- **Submission storage/history:** **PHP 8,000 to PHP 20,000**
- **Admin dashboard:** **PHP 15,000 to PHP 40,000**
- **Login/authentication:** **PHP 10,000 to PHP 25,000**
- **Real booking backend/system:** **PHP 25,000 to PHP 70,000+**
- **Payment gateway integration:** **PHP 15,000 to PHP 35,000+**
- **CMS/content editor:** **PHP 15,000 to PHP 40,000**

These are much more valuable than the base site because they move the project from brochure-site work into application/backend work.

#### Best pitch strategy for your current situation

Since you are still pitching the project, the best move is:

- keep the base website quote separate
- mention that the current forms are front-end only
- offer real email functionality as a paid add-on

This protects you from accidentally promising backend features for free.
